◆ getContent()

CloudRequestEngine::getContent ( flowData)
inline

Generate the Content to send in the POST request.

One name under several prefixes is sent once, with the value of the prefix that evidence.md ranks highest, being query, header, cookie, server, fiftyone and location, then any other prefix alphabetically. The groups are added lowest precedence first, so a later value replaces an earlier one. If there are evidence keys other than 'query.' that conflict then this is unexpected so a warning will be logged.

The engine sends every Evidence value in the Flow Data, including the values no element in the pipeline accepts, because what the cloud service uses changes over time and knowing about the other Evidence is important to continued optimization. The reserved names and the web request view are left out.

Parameters
{FlowData}flowData FlowData to get evidence from
Returns
{object} Evidence Dictionary

◆ reportPropertiesNotCovered()

CloudRequestEngine::reportPropertiesNotCovered ( flowData,
body )
inline

Compares the requested properties with an answer and logs, once, the names the answer left out.

The cloud service drops a property the keys do not cover without naming it, so only the engine can notice. A property present but null counts as answered, because its nullreason says why it has no value. The answer cannot change while the keys and the list stay the same, so one comparison is enough.

Parameters
{FlowData}flowData the flow data whose pipeline is logged to
{string}body the JSON the cloud service answered with
