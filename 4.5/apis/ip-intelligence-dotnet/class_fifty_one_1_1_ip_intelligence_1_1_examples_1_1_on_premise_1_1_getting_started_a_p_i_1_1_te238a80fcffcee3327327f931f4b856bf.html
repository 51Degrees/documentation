FiftyOne.IpIntelligence.Examples.OnPremise.GettingStartedAPI.Tests.NativeEngineLoadTests Class Reference

Detailed Description

Focused pre-flight checks for the native IP Intelligence engine that this project loads through its ASP.NET Core reference to GettingStarted-API.

These exist because a native-load failure normally surfaces only as an opaque wrapper — PipelineConfigurationException -> "The type initializer for '...IpIntelligenceEngineModulePINVOKE' threw an exception." — which hides the real Win32 reason. When one of these tests fails it names the actual cause directly, so the next regression is diagnosed from the assertion message alone instead of another round of ad-hoc logging.

History: the nightly Windows integration run failed here with 0x800700CE (ERROR_FILENAME_EXCED_RANGE) because the native DLL's dependency path exceeded MAX_PATH (260). This project's long directory name pushed the runtimes\win-x64\native</c> path to 255 chars on its own; the dependency the loader resolved next to it tipped over 260. The checkout directory is now shortened in CI, and NativeEngineDllPath_IsWithinWindowsMaxPath guards against the margin silently eroding again.
