FiftyOne.Pipeline.AgentSignature.Tests.SignatureTrustTests Class Reference

Detailed Description

Checks what a signature has to do before the element will say it proves anything, being that the key set comes from an address the agent controls rather than from the request itself, that the signature is tied to the request it arrived on, and that the agent it names is one the signature covers.

The signature times that no point in time can be written as are checked here as well, because they arrive through the same header.

◆ AgentHeaderTheSignatureDoesNotCoverIsNoAgent()

void FiftyOne.Pipeline.AgentSignature.Tests.SignatureTrustTests.AgentHeaderTheSignatureDoesNotCoverIsNoAgent ( )

Anyone can add a header to a request, so a 'Signature-Agent' header the signature does not cover says nothing about which agent sent the request.

A request whose signature covers '@authority' only, with a header bolted on naming an agent whose directory would verify it, reads Unverified with the NoAgent reason and fetches nothing.

◆ BareAgentComponentWithTwoMembersIsNoAgent()

void FiftyOne.Pipeline.AgentSignature.Tests.SignatureTrustTests.BareAgentComponentWithTwoMembersIsNoAgent ( )

A signature that covers the bare 'signature-agent' component covers the whole header, so the header has to name one agent for there to be no doubt which one signed.

Sent with two members, the element picks neither and reads Unverified with the NoAgent reason, even though the first member names the agent whose keys this harness serves. The same bare component with one member is the form the architecture v1 vectors send, and those verify, so this is about the count rather than the form.

◆ CreatedTimeOutsideTheRangeOfTimesIsAnswered()

void FiftyOne.Pipeline.AgentSignature.Tests.SignatureTrustTests.CreatedTimeOutsideTheRangeOfTimesIsAnswered ( string created)

A 'created' far outside the range of times the framework can hold is answered rather than thrown out of the pipeline.

Such a value names no time at all, so the signature parameters cannot be read and the request reads Invalid with the Malformed reason. Reading it as the earliest time instead would let a signature claiming a created far in the future pass as one made long ago.
