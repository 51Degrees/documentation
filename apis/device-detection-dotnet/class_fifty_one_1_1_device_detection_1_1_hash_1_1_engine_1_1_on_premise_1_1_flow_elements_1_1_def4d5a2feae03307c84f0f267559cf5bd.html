If set to false, a non-matching User-Agent will result in properties without set values.

If set to true, a non-matching User-Agent will cause the 'default profiles' to be returned. This means that properties will always have values (i.e. no need to check .HasValue) but some may be inaccurate.. By default, this is false.

◆ SetConcurrency()

override DeviceDetectionHashEngineBuilderBase< TEngine > FiftyOne.DeviceDetection.Hash.Engine.OnPremise.FlowElements.DeviceDetectionHashEngineBuilderBase< TEngine >.SetConcurrency ( ushort concurrency)

Set the expected number of operations that use the engine at the same time.

The native code uses it for every collection read from the data file. First, it sets the number of file handles in the pool, which is the concurrency up to a fixed maximum of 64, because a process can only have so many files open. An operation that has to read from the file when every handle is in use waits until another operation releases one. Second, it decides how each cache is split into parts, each with its own lock, which avoids excessive locking. An item in use cannot be removed from a cache, and any operation can need any part, so every part holds at least the concurrency in items. The number of parts is the concurrency, or fewer where needed so that every part holds that many items, and a cache that holds fewer items than the concurrency in total is made large enough to hold that many. No value stops the engine building. The concurrency has no effect when every collection is held in memory, for example with the MaxPerformance profile.

Parameters
concurrencyThe expected number of operations that use the engine at the same time.

override DeviceDetectionHashEngineBuilderBase< TEngine > FiftyOne.DeviceDetection.Hash.Engine.OnPremise.FlowElements.DeviceDetectionHashEngineBuilderBase< TEngine >.SetUsePerformanceGraph ( bool use)

Specify if the 'performance' evaluation graph should be used or not.

The performance graph is faster than predictive but can be less accurate. Note that the performance graph will always be evaluated first if it is enabled so if you have both performance and predictive enabled, you will often be getting results from just the performance graph. In that situation, predictive will only be used if a match cannot be found using the performance graph.

Parameters
useTrue to use the performance graph, false to ignore it.
