FiftyOne.DeviceDetection.Example.Tests.Shared.TestDiscoveryGuard Class Reference

Detailed Description

Guards against test classes that the MSTest adapter cannot discover.

When a class carries a fixture attribute on a method with the wrong signature, for example a [ClassInitialize] method that is not static, MSTest writes a discovery message to the console and then drops the whole class. Every test in that class stops running, the exit code stays zero and the run still reports "Passed!". Nine Selenium classes in this repository were dropped that way and nobody noticed, because a warning that nothing reads is the same as no warning at all.

This file is linked into every test project, see the Tests\Shared Compile item in each .csproj, so that each test assembly checks itself. The rules the adapter applies are checked here by reflection and a breach fails as a normal test, which turns a silent drop into a red run.

Every type in the assembly is checked, not only the ones marked [TestClass], because base classes carry fixture methods too and a base class with a bad fixture drops every class beneath it.
